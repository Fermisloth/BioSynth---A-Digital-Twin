 # BioSynth Data Dictionary

 This document explains the data fields in plain language. “Synthetic” means the value was generated by the project for a controlled proof of concept; it does not mean the value came from a real patient.

 ## 1. Data layers

 | Layer | Location | What it represents |
 | --- | --- | --- |
 | Real CGM evidence | Hall-derived reports | Used only to test whether CGM trajectory signal exists in real data. |
 | Synthetic raw CGM | `data/02_synthetic/cgm/` | Timestamped glucose readings for 100 virtual participants. |
 | Synthetic participant metadata | `data/02_synthetic/metadata/synthetic_participants.csv` | Simulator context and phenotype labels used for analysis. |
 | Synthetic event metadata | `data/02_synthetic/metadata/synthetic_events.csv` | Simulator disturbances and ground truth; excluded from predictive inputs. |
 | Synthetic static EHR | `data/02_synthetic/ehr/synthetic_ehr.csv` | One generated health profile per virtual participant. |
 | Feature tables | `reports/` | Training rows containing labels and numeric model features. |

 ```mermaid
 flowchart LR
   CGM[Raw synthetic CGM<br/>timestamp + glucose] --> TRAJ[18 CGM trajectory features]
   EHR[Static synthetic EHR<br/>one row per participant] --> ENCODE[11 encoded EHR features]
   META[Participant and event metadata] -. context and labels only .-> LABEL[Training label]
   TRAJ --> JOIN[Participant + timestamp join]
   ENCODE --> JOIN
   LABEL --> JOIN
   JOIN --> TABLE[198,000-row fusion feature table]
 ```

 ## 2. Raw CGM fields

 | Field | Example | Meaning |
 | --- | --- | --- |
 | `timestamp` | `2026-01-04 12:10:00` | When the sensor reading occurred. |
 | `glucose_value_mg_dl` | `176.5` | Glucose value in milligrams per deciliter. |

 The synthetic generator uses five-minute intervals. Each participant has 7 days of readings, giving 2,016 readings per participant and 201,600 raw observations overall.

 ## 3. Static EHR fields

 | Field | Meaning | Used in fusion model? |
 | --- | --- | --- |
 | `person_id` | Participant identifier used for joining files. | No. |
 | `simulation_phenotype` | Simulator grouping such as No diabetes-like, Prediabetes-like, or T2D-like. | No. |
 | `age_years` | Synthetic age in years. | Yes, numeric encoding. |
 | `sex` | Synthetic sex category. | Yes, one-hot encoding. |
 | `bmi_kg_m2` | Synthetic body mass index. | Yes, numeric encoding. |
 | `hba1c_percent` | Synthetic HbA1c percentage. | Yes, numeric encoding. |
 | `fasting_glucose_mg_dl` | Synthetic fasting glucose. | Yes, numeric encoding. |
 | `family_history_diabetes` | Synthetic family-history indicator. | Yes, 0/1 encoding. |
 | `hypertension_history` | Synthetic hypertension-history indicator. | Yes, 0/1 encoding. |
 | `activity_level` | Synthetic low/moderate/high activity category. | Yes, one-hot encoding. |
 | `synthetic_data_note` | Text warning that the record is not real clinical data. | No. |

 There must be exactly one EHR record per participant. The dashboard currently selects `SYN-0085` by `person_id` and verifies that the match is neither missing nor duplicated.

 ## 4. EHR encoding

 The runtime and the fusion feature builder use the same encoding:

 | Original field | Model columns | Encoding |
 | --- | --- | --- |
 | `age_years` | `ehr_age_years` | Numeric copy. |
 | `bmi_kg_m2` | `ehr_bmi_kg_m2` | Numeric copy. |
 | `hba1c_percent` | `ehr_hba1c_percent` | Numeric copy. |
 | `fasting_glucose_mg_dl` | `ehr_fasting_glucose_mg_dl` | Numeric copy. |
 | `family_history_diabetes` | `ehr_family_history_diabetes` | 0 or 1. |
 | `hypertension_history` | `ehr_hypertension_history` | 0 or 1. |
 | `sex` | `ehr_sex_female`, `ehr_sex_male` | One-hot encoding. |
 | `activity_level` | `ehr_activity_low`, `ehr_activity_moderate`, `ehr_activity_high` | One-hot encoding. |

 ## 5. The 18 CGM trajectory features

 | Feature | Meaning |
 | --- | --- |
 | `current_glucose_mg_dl` | Latest glucose in the historical window. |
 | `current_is_high` | 1 if current glucose is above 180; otherwise 0. |
 | `history_mean_glucose` | Average glucose over the window. |
 | `history_median_glucose` | Middle glucose value in the window. |
 | `history_min_glucose` | Lowest glucose in the window. |
 | `history_max_glucose` | Highest glucose in the window. |
 | `history_range_glucose` | Maximum minus minimum glucose. |
 | `glucose_change_15m` | Latest value minus value about 15 minutes earlier. |
 | `glucose_change_30m` | Latest value minus value about 30 minutes earlier. |
 | `glucose_change_60m` | Latest value minus value about 60 minutes earlier. |
 | `glucose_slope_per_hour` | Overall fitted rate of change in mg/dL/hour. |
 | `history_std_glucose` | Sample standard deviation of glucose. |
 | `history_cv_glucose` | Standard deviation divided by mean. |
 | `history_high_count` | Number of readings above 180. |
 | `history_high_fraction` | High-reading count divided by usable-reading count. |
 | `history_minutes_above_180` | Approximate observed minutes above 180. |
 | `trajectory_numeric_count` | Number of usable numeric readings. |
 | `trajectory_actual_history_minutes` | Time span covered by usable readings. |

 ## 6. Labels and event fields

 | Field | Meaning | Predictive input? |
 | --- | --- | --- |
 | `pre_event_target` | 1 when a new event begins within the next 120 minutes; otherwise 0. | No; it is the answer being predicted. |
 | `event_id` | Identifier for an observed/detected event. | No. |
 | `event_status` | Event context such as pre-event or underway. | No. |
 | `future_max_glucose_mg_dl` | Future maximum used for analysis/labeling. | No. |
 | `future_hyperglycemia` | Future event indicator. | No. |
 | `simulation_phenotype` | Simulator group. | No. |

 A model input must describe the past or present. A label is allowed to describe the future because training needs a known answer, but the label must never be placed among the features.

 ```mermaid
 flowchart TD
   NOW[Prediction timestamp] --> HISTORY[CGM readings at or before timestamp]
   HISTORY --> INPUT[Allowed model features]
   NOW --> FUTURE[Next 120 minutes]
   FUTURE --> ANSWER[pre_event_target label]
   ANSWER -. training answer only .-> TRAIN[Model training]
   FUTURE -. blocked from runtime features .-> INPUT
 ```

 ## 7. Dataset sizes

 | Dataset | Rows | Participants | Purpose |
 | --- | ---: | ---: | --- |
 | Raw synthetic CGM | 201,600 | 100 | Input sensor stream. |
 | Synthetic prediction rows | 198,000 | 100 | Candidate prediction timestamps and labels. |
 | Synthetic fusion features | 198,000 | 100 | 18 CGM + 11 EHR model inputs. |
 | Synthetic EHR | 100 | 100 | One static profile per participant. |
 | Hall feature rows | 89,329 | 57 | Real-world proof-of-signal branch. |
